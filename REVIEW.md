# Разбор решения v1 (`deck-designer`) и что изменено в v2

Разбор сделан по коду v1, по трём шаблонам датасета (отрендерены через PowerPoint) и по файлам,
которые v1 оставил в `data/outputs/` (`local_balanced/visual/compact.pptx`).

## Коротко

Каркас v1 правильный: слои общаются через pydantic-модели, промпты версионируются, проверки
регистрируются декоратором, конфиг один, есть идея «эталон геометрии — шаблон». Главная ошибка —
в стратегии сборки слайда. v1 не использует слайд-образец, а **рисует слайд заново**: берёт пустой
макет, удаляет его плейсхолдеры и ставит текстовые рамки и прямоугольники со сплошной заливкой.

В датасете дизайн живёт в слайдах-образцах, а не в макетах: градиенты, скругления, группы, иконки,
картинки, декор. Поэтому при перерисовке он пропадает. На готовых слайдах v1 видны заглушки
«Заголовок-вывод слайда», «2,3 ч», «Текст абзаца», пустые серые подложки и потерянный декор. Это бьёт
сразу по трём критериям: «соответствие стилю», «адаптация к шаблону» и «качество презентаций».

v2 построен иначе. Единица генерации — **клон слайда-образца с правками**: заменить текст с сохранением
стиля рана, удалить лишние карточки и распределить оставшиеся, поставить нативный график на место
картинки-примера. Это edit-based подход, как в PPTAgent. Аудит проверяет **готовый .pptx**, а не
промежуточное представление.

## Что было хорошо и сохранено

| v1 | в v2 |
|---|---|
| Слои parsing → planning → composing → audit → export, контракты в `models.py` | сохранено, контракты переписаны под edit-based подход |
| Промпты отдельными файлами + `registry.yaml` + закрепление версий в `config.yaml` | сохранено, добавлены **скиллы** (блоки знаний с версиями), которые агенты подключают |
| Реестр проверок `@check`, каталог для AUDIT.md из кода | сохранено; каталог + тест, что у каждой проверки есть тест |
| «Эталон геометрии — шаблон» (`template_box`) | развито: аудит сравнивает каждую фигуру готового файла с её фигурой в образце |
| Цифры в слотах-показателях только из источников | развито: общая детерминированная сверка `content/grounding.py` + проверка `content.numbers_grounded` |
| Параллельные запросы к vLLM, кэш разбора по хэшу | сохранено |

## Проблемы v1 (по убыванию влияния на оценку)

### 1. Дизайн шаблона теряется при сборке (критично)
- `composing/composer.py` собирает слайд из `ShapeElement(geometry="rect", fill=...)`, а `export/pptx_writer.py`
  создаёт слайд на **пустом макете**, удаляет его плейсхолдеры (`for ph in slide.placeholders: remove`) и рисует
  фигуры заново.
- Теряются: градиенты (в WorkSpace 30 `gradFill`), скругления (`roundRect` с adj), группы, контуры, тени, картинки
  внутри карточек, стиль абзацев (интерлиньяж, отступы, маркеры), цвета из темы.
- Заголовок перестаёт быть плейсхолдером (outline view, доступность), а «слайд на макете шаблона» формально
  выполнен, но визуально нет.
- **v2:** `render/pptx_builder.py` клонирует слайд-образец целиком (фон, все фигуры, связи с картинками и
  графиками, clrMapOvr) и правит только текст/состав. Стиль берётся из рана-образца с текстом (пустые раны
  Google Slides с чёрным цветом по умолчанию пропускаются).

### 2. Парсер ошибается на реальных шаблонах датасета
Проверено на трёх шаблонах:

| дефект v1 (`parsing/pptx_reader.py`) | сколько в датасете | последствие |
|---|---|---|
| не применяется трансформация группы (`chOff/chExt`) | 44 группы | координаты карточек внутри групп неверны |
| `.//a:r` у группы собирает раны детей | 43 группы | текст и ёмкость считаются дважды |
| кегль без явного `sz` не наследуется (layout/master/lstStyle) | ≈10% ранов (170 из 1757) | шкала кеглей неполная, ёмкость слотов неверна |
| плейсхолдер без своего `xfrm` отбрасывается (`w<=0 → continue`) | 0 в датасете, **типично для PowerPoint-шаблонов** | на незнакомом шаблоне теряются заголовки и тела |
| цвета только из первой темы, без `clrMap` | в VK Tech 2 мастера | `scheme:tx1/bg1` не разрешаются, контраст считается по умолчаниям |
| `normAutofit fontScale`, `wrap="none"`, прозрачность заливки, цвет из `p:style` не читаются | «43%» в Education = 239 pt ×37% | ложные переполнения, неверный контраст |

**v2:** `ooxml/reader.py` разрешает группы, наследование плейсхолдеров и стилей по цепочке
shape → layout → master → txStyles/defaultTextStyle, темы каждого мастера с clrMap, fontScale, wrap, alpha,
fontRef. Покрыто `tests/unit/test_reader.py`.

### 3. Шаблон без слайдов-образцов не поддерживается
На финале будет незнакомый шаблон. Чистый PowerPoint-шаблон (`.pptx`/`.potx`) часто содержит **только макеты**.
v1 строит паттерны только из слайдов и на таком файле не найдёт ни одного макета.
**v2:** `parsing/template.py: prepare_template` создаёт виртуальный образец для каждого макета без слайда
(плейсхолдеры с демо-текстом). Проверено тестом на стандартном шаблоне PowerPoint без единого слайда.

### 4. Text-to-image и «встраивание изображений» не подключены
`make_t2i` нигде не вызывается, промпт `image_prompt` не используется. Фото шаблона v1 выбрасывает, и в макетах
остаются дыры (белые рамки «Вставить фото»). Критерий 3 ТЗ прямо называет «встраивание изображений».
**v2:** `images/provider.py`: сначала картинка из контент-пакета, затем FLUX.2-klein-4B (Apache 2.0) с проверкой
свободной VRAM, иначе слот удаляется вместе с рамкой. Демо-фото, зашитые в макет, распознаются
(JPEG/имя макета), и такие образцы не выбираются.

### 5. Аудит проверяет промежуточное представление, а не файл; часть исправлений не существует
- Проверки работают по `DeckIR`, то есть по тому, что генератор *собирался* сделать. Готовый файл проверяют
  только «открывается» и «не растр».
- В AUDIT.md заявлены исправления `snap_x`, `fit_image`, `snap_logo`, `split_slide`, `shorten_text`,
  `rewrite_text`, но в `audit/fixes.py` их нет. Галочка в UI ничего не делает, и это молча.
- **v2:** проверки читают итоговый .pptx (`audit/base.py: AuditContext`). У каждой проверки есть реализованное
  исправление или явная пометка «только показать». Исправления меняют план, после чего колода
  пересобирается и перепроверяется. VLM-исправления идут через агента `rewrite`.

### 6. Пользователь не может ввести свой текст
UI v1 принимает только **путь к папке контент-пакета на сервере**. Загрузить текст или материалы нельзя,
а задача — «финальные презентации с учётом выбранной темы и текста пользователя».
**v2:** в UI есть текстовое поле и загрузка материалов (csv/xlsx/md/txt/docx/pdf/картинки). Факты с цифрами
извлекаются из текста детерминированно, таблицы берутся из файлов, ряды чисел из текста агент `skeleton`
выносит в таблицы со сверкой каждой цифры.

### 7. Безопасность API
- `POST /api/templates/upload` пишет по `file.filename` без очистки (`../../…` — запись вне папки).
- `POST /api/audit/fix` и `/api/export` принимают произвольные `deck_ir_path` и `template_path`: чтение и запись
  JSON в любом месте сервера.
- `generate` меняет общий `settings.run.target_slides`: гонка между параллельными задачами.
- **v2:** имена файлов очищаются, все пути проверяются `is_relative_to` рабочих папок (тест обхода даёт 404),
  параметры прогона не трогают общий конфиг.

### 8. Модель и железо
- Документы v1 рассчитаны на **RTX 6000 Ada**, а сервер — **RTX A6000 (Ampere)**. На Ampere нет FP8-ядер:
  FP8-веса исполняются Marlin-ядрами W8A16, FP8 KV-кэш недоступен. Флаги и оценки памяти нужно было пересчитать.
- В MODELS.md v1 противоречие: основной указан Qwen3.6-27B-FP8, а в «Запуск локально» — `Qwen3-32B` +
  `Qwen2.5-VL-32B`. В `pyproject` extra `vllm>=0.6` не поддерживает Qwen3.6/3.8.
- **v2:** Qwen3.8-27B (вышла в августе 2026, Apache 2.0, та же модель, что обещана в инференсе VK для топ-10),
  FP8-чекпойнт, флаги и профили памяти под A6000. См. MODELS.md.

### 9. Графики, иконки, размер файла
- Все серии таблицы на одной оси (люди 420 и проценты 71). На тёмном шаблоне WorkSpace подписи осей по
  умолчанию чёрные на чёрном, сетка захардкожена `E1E1E1`.
- `_pick_asset` ставит **одну и ту же иконку** во все слоты: VLM-вопрос 6 «иконки относятся к теме» гарантированно «нет».
- Готовый .pptx весит 18 МБ, из них 17 МБ — картинки неиспользованных макетов.
- **v2:** цвета серий из палитры с контрастом к фону слайда, подписи цветом текста шаблона для тёмного или
  светлого фона, несопоставимые серии не смешиваются. Иконки остаются иконками образца. Неиспользованные
  макеты и мастера вычищаются: 2–4 МБ вместо 18.

### 10. Устойчивость и тесты
- Если модель недоступна или сломала JSON, колоды нет: на критерий «устойчивость» ответа нет.
- `tests/fixtures/` пуст, на реальных шаблонах тестов нет, e2e только с моделью.
- **v2:** `fallback_to_offline`: эвристический каркас и писатель, колода собирается всегда. 30 тестов без GPU,
  в том числе e2e на трёх шаблонах и на незнакомом шаблоне, тест покрытия реестра проверок.

### Мелочи
«Спасибо за внимание» зашито по-русски вне зависимости от языка. Заголовок-вывод режется посреди слова. Стоп-слово
«фото» в тексте слайда превращало 3D-декор VK Tech в «фото» и удаляло его. У `layout.margins`/`alignment`
вообще не было эталона для новых фигур.

## Итерация 2: текст на графике и читаемость (по скриншотам пользователя)

| проблема на скриншоте | причина | исправление |
|---|---|---|
| Education, обложка: заголовок чёрный и уходит под паттерн | паттерн лежит в макете одной картинкой на полслайда и отсекался фильтром по площади; пустой плейсхолдер без демо-текста получал кегль 32 и чёрный цвет по умолчанию; аудит по WCAG 2 «исправлял» белый на синем в чёрный (4.1 → 5.1:1) | карта занятости по пикселям (`parsing/occupancy.py`), стиль пустого плейсхолдера наследуется из макета (Play 60 pt, белый), контраст и автоисправление — по APCA |
| VK Tech, титул: «Запуск VK WorkSpace…» | обрезка с многоточием | обрезка только по границе фразы/слова, служебное слово в конце убирается, «…» нет нигде; заголовок может уменьшиться до 70% кегля |
| VK Tech, карточка с 3D-шаром: текст на шаре | рамка текста целиком внутри картинки-карточки, прямоугольники не пересекаются | рамка — свободная часть карточки над объектом; высота — не больше текста дизайнера × 1,25 (светлый верх шара на светлой карточке по цвету не отличить) |
| VK Tech, кольца: «2,3 ч» налезает на кольцо | старое правило сужало рамку цифры до 0,05; строка без переноса могла расти в 1,6 раза | цифра растёт только до кольца, в «дырке» которого стоит (слой с прозрачным центром) |
| Education, круговая схема: подписи с «…» | обрезка с многоточием | см. выше; модель получает лимит строк и подсказку «рядом графика — не длиннее образца» |
| чёрный текст на холодных цветах | нейтральный цвет шаблона на синей плашке; решение по WCAG 2 | при сборке нейтральный текст с APCA ниже порога перекрашивается в цвет текста шаблона; мелкий акцентный текст осветляется в том же оттенке |

Попутно: подпись «33%» в Education переносилась по невидимой части рамки за краем слайда — рамки режутся по
краю слайда; заголовок с автоподбором высоты рос на пустой подзаголовок обложки — пустые плейсхолдеры теперь
препятствие; зеркальная картинка-свечение (flipH) давала ложный край — ридер читает flipH/flipV.
