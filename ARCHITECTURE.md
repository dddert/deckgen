# Архитектура

```
 .pptx шаблон ─► [1 parsing] ─► TemplateModel = DesignSystem + TemplateSlide[] (разобранные слайды-образцы)
                     │  ooxml/reader: группы, наследование slide→layout→master, темы/clrMap, fontScale, alpha
                     │  analyzer: слоты текста, элементы (карточки), картинки, место под график, тип образца
                     │  (+ VLM уточняет тип по рендеру; + виртуальные образцы для шаблона без слайдов)
                     ▼
 текст + файлы ─► [2 content] ─► ContentPack (факты с цифрами — детерминированно, таблицы из csv/xlsx)
                     ▼
               [3 planning] ─► Outline: состав, порядок, заголовки-выводы, число элементов, данные (1 вызов LLM)
                     ▼
        ┌── [4 composing ×3 варианта, параллельно] ────────────────────────────────────────────────┐
        │  variants: политика варианта → selector: образец под каждый слайд →                      │
        │  writer: тексты под слоты образца (параллельно, JSON-схема = слоты) → fitter: кегль из шкалы│
        │  → shorten → charts: нативный график/таблица на место примера → images: пакет / FLUX         │
        │  ─► DeckPlan: для каждого слайда «клон образца N + правки»                                  │
        └──────────────────────────────────────────────────────────────────────────────────────────┘
                     ▼
               [5 render] pptx_builder: клон образца + правки → .pptx (нативные объекты)
                     ▼            office: .pptx → .pdf → PNG (LibreOffice)
               [6 audit]  26 детерминированных проверок по ГОТОВОМУ файлу (эталон — образец)
                     │    → auto-fix (конфиг) → пересборка → повторный аудит
                     │    → 14 VLM-вопросов по PNG (недетерминированные)
                     ▼
               [7 export] .pptx · .pdf · .html (нативный HTML из итогового файла)
                     ▼
               UI: замечания с подсветкой → пользователь выбирает исправления → пересборка → аудит
```

Слои общаются только моделями из `src/deckgen/models.py`. Ни один слой, кроме `llm/`, не знает о модели.
Все артефакты прогона лежат в `data/outputs/runs/<run>/`:
`pack.json`, `outline.json`, `<variant>/{outline,plan,audit}.json`, `deck_<variant>.{pptx,pdf,html}`, `png/`.

## 1. Parsing — `deckgen.parsing`, `deckgen.ooxml`

**Главная находка по датасету:** дизайн живёт в слайдах-образцах, а не в макетах. В WorkSpace все 15 макетов
содержат только заголовок, в VK Tech 36 из 54 слайдов на макете «Свободный дизайн». Поэтому единица
переиспользования — **слайд-образец**, а генерация — **его клон с правками** (edit-based, как PPTAgent),
а не перерисовка на пустом макете, как в v1.

| модуль | что делает |
|---|---|
| `ooxml/reader.py` | фигуры с абсолютной геометрией (трансформации групп), текст с вычисленным стилем (цепочка shape lstStyle → layout → master → txStyles/defaultTextStyle), цвета через тему своего мастера и clrMap, fontScale, wrap, alpha, фон слайда/макета/мастера, декор макета |
| `ooxml/colors.py` | scheme/sys/prst цвета, lumMod/lumOff/tint/shade; контраст WCAG 2 (для отчёта) и **APCA** (решения): `apca_lc`, `best_text_color`, `readable_tint` — тот же оттенок акцента, осветлённый до порога читаемости |
| `parsing/analyzer.py` | роли текстовых слотов (title/subtitle/heading/body/bullets/number/ordinal/label/name/caption), **элементы** — повторяющиеся карточки (кластеризация фигур по форме/размеру, вложенность, параллельные ряды: номер над подписью, дата над описанием), составные слоты («ХХ% + подпись»), ёмкость по метрикам шрифта с учётом блоков ниже, рамки в пределах слайда и карты занятости (`occupancy.py`), пустой плейсхолдер под заголовком обложки — подзаголовок, расширяемая рамка заголовка, картинки (декор/логотип/иконка/фото/пример графика), место под график (нативный график/таблица → пример-картинка → заглушка «Иллюстрация» → тело текста → самый большой пустой прямоугольник), тип и пригодность образца |
| `parsing/occupancy.py` | **карта занятости под текстом**: слои под рамкой сводятся в растр ~480 px (прозрачность, обрезка, зеркалирование картинок), по нему — карта краёв (лапласиан) и верхнего непрозрачного слоя. Рабочая рамка текста — наибольший свободный прямоугольник вокруг начала текста: не заходит на край объекта (паттерн обложки, обод шара на карточке), на кольцо, в «дырке» которого стоит цифра, и туда, где текст стал бы нечитаем; бледная подложка, зерно и свечение фона не препятствие. Там же — цвет фона под текстом для APCA. Текст на картинке-карточке ограничен высотой текста дизайнера |
| `parsing/design.py` | палитра с ролями, гарнитуры по реальному тексту (тема «врёт»: Arial в теме, Play в тексте), шкала кеглей, безопасная область, цвета текста для светлого и тёмного фона |
| `parsing/fonts.py` | метрики текста: TTF гарнитуры (assets/fonts ← Google Fonts), иначе прокси-шрифт с запасом |
| `parsing/template.py` | вход слоя, кэш по хэшу файла + версии парсера; **виртуальные образцы** для макетов без слайдов; дубли и служебные слайды (код, библиотеки иконок, Гант) исключаются |
| `pipeline/classify.py` | VLM подтверждает или исправляет тип образца по рендеру (эвристика подаётся как гипотеза) |

### Работа с неопределённостью (незнакомый шаблон на финале)
- Ничего не привязано к именам макетов и текстам датасета. Роли и типы выводятся из структуры: плейсхолдеры,
  повторы, вложенность, числовые заглушки. Ключевые слова заголовка — только подсказка.
- Шаблон без слайдов-образцов получает виртуальные образцы по плейсхолдерам макетов. Имя макета («Title Slide»,
  «Two Content») учитывается **только** для таких образцов: Google Slides называет макеты «N_Титульный слайд»
  даже у контентных слайдов.
- Нет образца нужного типа — цепочка замен (`planning/skeleton.py: FALLBACK`), для данных — любой образец с
  местом под график.
- Нет места под график — свободная область под заголовком (поиск максимального пустого прямоугольника).
- Нет шрифта на сервере — прокси-метрика с запасом ширины. Fitter и аудит считают одинаково.

## 2. Content — `deckgen.content`

Вход — **текст пользователя** плюс необязательные файлы (csv/xlsx → таблицы, md/txt/docx/pdf → текст, картинки → ассеты)
или папка контент-пакета формата v1. Каждое предложение с цифрой становится фактом `f1…fn`. Это единственный
источник цифр для слайдов и для проверки «все цифры есть в материалах» (`content/grounding.py`).

## 3. Planning — `deckgen.planning`

Один короткий вызов на колоду (`skeleton`). Модель видит каталог типов слайдов **этого** шаблона с числами элементов,
под которые есть макеты. Она возвращает слайды: тип, заголовок-вывод, мысль, число элементов, черновые тезисы,
ссылки на факты, данные для графика, описание иллюстрации. Ряды чисел из текста можно вынести в таблицу, но
каждая цифра сверяется с исходным текстом. Всё проверяется детерминированно (`normalize`): типы приводятся к
доступным, число элементов — к существующим макетам, первый слайд титул, последний «Спасибо», если он есть в шаблоне.
Без модели каркас строит эвристика.

## 4. Composing — `deckgen.composing`

- `selector` — прозрачный скоринг образца: тип (и цепочка замен) → точное число элементов → место под график →
  фото (есть ли чем заполнить) → ёмкость текста → вмещается ли заголовок → плотность под вариант → однородность
  светлых/тёмных слайдов → уверенность разбора → разнообразие (штраф за повтор). Вариант берёт k-й из близких к
  лучшему.
- `writer` — JSON-схема ответа строится **под слоты образца**: ключ — id фигуры, список — для списков и составных
  слотов ровно с числом частей образца. Модель не может пропустить слот. Дальше идёт чистка: маркеры, id фактов,
  демо-текст шаблона, выдуманные цифры.
- `fitter` — кегль только из шкалы шаблона и не ниже `min_font_scale`. Расширенная рамка заголовка. Высота
  spAutoFit-рамок. Строка без переноса для крупных цифр.
- `composer` — лишние элементы удаляются, оставшиеся центрируются с исходным шагом, ритм дизайнера сохраняется.
  Незаполненные слоты удаляются (подложки очищаются), заглушек не остаётся. Удалённое «Имя Фамилия» уносит
  кружок-аватар. Зона графика очищается от подписей и линий примера. Порядковые номера «01…» ставятся без модели.
- `charts` — тип графика по данным (время → line, доли → doughnut, длинные подписи → bar), серии с несопоставимым
  масштабом не смешиваются. Цвета — палитра с контрастом к фону слайда, подписи — цвет текста шаблона для тёмного или
  светлого фона. Таблица ≤ 7×5, график ≤ 5 серий.

### Три варианта вёрстки (п. 5 ТЗ) — ось «плотность ↔ визуальность»

| вариант | состав | макеты | данные | тексты |
|---|---|---|---|---|
| **Сбалансированный** | одна мысль на слайд | лучшие по совпадению | графики | 80% ёмкости слота |
| **Визуальный** | + разделитель перед блоком цифр | с картинками/графикой, фактоиды | цифры → фактоиды, таблицы → графики, иллюстрации | 60%, ≤ 3 тезисов |
| **Компактный** | −25–35% слайдов: соседние тезисные сливаются в карточки, без разделителей и содержания | плотные | графики → таблицы (где ≤ 7×5) | 95%, до 6 тезисов |

Почему эта ось: она меняет сразу состав, макеты и способ показа данных, поэтому варианты визуально различимы
(e2e-тест проверяет, что у трёх вариантов разные наборы образцов и разное число слайдов). При этом все три
собираются только из образцов шаблона: палитра, шрифты, макеты и логотипы общие, и template-проверки проходят
одинаково.

## 5. Render / export — `deckgen.render`

- `pptx_builder` — открывает шаблон, для каждого слайда плана **клонирует образец**: фон, все фигуры, связи с
  картинками, графиками и гиперссылками (с переназначением rId), clrMapOvr, showMasterSp. Затем правки: текст в
  раны-образцы (стиль рана с текстом, a:br, per-part стиль составных слотов), перемещения, новые рамки, картинки
  (crop-to-fill через srcRect), нативный график или заполнение нативной таблицы образца, точечные стилевые правки
  аудита, удаление фигур. Образцы шаблона удаляются, неиспользованные макеты и мастера вычищаются.
- `office` — .pptx → .pdf → PNG: LibreOffice headless (отдельный профиль на вызов). На macOS без LibreOffice —
  PowerPoint через AppleScript, для отладки.
- `html` — нативный HTML из итогового .pptx: фон, декор макета, фигуры, текст, таблицы, SVG-графики, навигация
  стрелками.

## 6. Audit — `deckgen.audit` (часть пайплайна)

`compose → build → render → детерминированный аудит → auto-fix → build → аудит → VLM-аудит → export`.
Подробности — [AUDIT.md](AUDIT.md). Ключевое отличие от v1: проверки читают готовый файл и сравнивают его с
образцом. Ошибкой считается то, что внёс генератор, а не замысел дизайнера.

## 7. Версионирование скиллов и агентов (п. 4 ТЗ)

`prompts/<агент>/vN.md` — промпты, `skills/<скилл>/vN.md` — переиспользуемые блоки знаний (сторителлинг, лимиты
плотности, визуализация, работа со слотами шаблона, визуальная проверка). В `prompts/registry.yaml` у каждой версии
агента явно перечислены скиллы с версиями. Закреплённые версии задаются в `config.yaml: prompts.*`. Использованные
версии агентов и скиллов записываются в `plan.json` и `audit.json`. Файл версии не редактируется: новая версия +
changelog. Каталог — `deckgen prompts` или `GET /api/prompts`.

## 8. API и UI

FastAPI (`api/app.py`) + React/TypeScript (`web/`). Шаги: выбор или загрузка шаблона (разбор, палитра, типы,
превью образцов) → текст и файлы → прогресс по этапам → три варианта с превью и скачиванием → аудит: слайд с
подсветкой замечаний, выбор исправлений, пересборка. Задачи фоновые, не больше двух генераций одновременно на
одну GPU. Пути к файлам проверяются на выход за рабочие папки.

## 9. Устойчивость

- Модель недоступна или сломала JSON → повтор с ошибкой → эвристика (`fallback_to_offline`). Колода собирается всегда.
- Нет LibreOffice → нет PDF/PNG и VLM-аудита, а .pptx/.html и детерминированный аудит работают. UI показывает причину.
- Нет VRAM для text-to-image → картинки из пакета/шаблона.
- Сломанная проверка не роняет аудит, неудачное исправление не роняет остальные.
